## UI5_BOOTSTRAP_EXTERNAL

**An HTML page bootstraps SAPUI5 from an external host without an `integrity` attribute.** The bootstrap script (`sap-ui-core.js`) runs with the full authority of the page: it initializes the runtime and then fetches every library, control and resource the app needs from the same origin at run time. When that origin is a public CDN the application executes whatever the CDN serves, and with the unversioned URL form (`https://ui5.sap.com/resources/sap-ui-core.js`) that code changes whenever SAP publishes a new maintenance version, without a deploy and without a trace in the project. A compromised or spoofed CDN response, a DNS or proxy manipulation on the user's network, or simply an incompatible new version then reaches every user session. An `integrity` attribute lets the browser refuse a loader that does not match the expected hash; it is a partial defence (it covers only the one script, not what the loader fetches afterwards), but together with a pinned version it is the most the page itself can do when the CDN stays.

- **Data:** every `*.html` file outside the skipped directories, recorded in `html[]` when it contains a `<script>` with `id="sap-ui-bootstrap"` or a `src` ending in `sap-ui-core.js`: the relative file name, the line of the script tag, the `src` reduced to origin and path (userinfo, query and fragment are dropped; `[non-http]` for other schemes), `external` (absolute `http(s)` URL), `integrity` (attribute present; its value is never stored), `versionForm` (`specific` for a `/1.120.3/` segment, `evergreen` for `/1.120/`, `latest` for an external URL without either, `none` for a relative src) and `testPage` (a `test/` path segment, or a file name like `flpSandbox.html` or `*.qunit.html`).
- **Trigger:** a bootstrap with `external === true` and `integrity === false`. One finding per HTML file per project; the subject is the relative file name. When a file holds several such bootstraps the one with the unpinned `latest` form on a non-test page wins, otherwise the first in the file.
- **Severity:** from the criticality matrix, both inputs recorded in the evidence.
  - `medium` (impact `moderate`, ease of attack `advanced`) when `versionForm` is `latest` and the page is not a test page: the code the users run changes with every CDN release, and nobody can say which version ran when.
  - `low` (impact `minor`, ease of attack `complex`) otherwise: a `specific` or `evergreen` version still trusts the host, but a swap would have to target a fixed artifact; a test page (`flpSandbox.html`, QUnit pages, anything under `test/`) is a development aid and not what end users open. (The design table wrote this cell as `minor` × `advanced`, which the matrix maps to `medium`; `complex` is the pair that yields the intended `low`.)
- **Evidence:** `subject` (HTML file), `host` (the host name of the `src`, or `null` when the `src` is not an absolute URL with a DNS-shaped host; never the path, port, userinfo, query or fragment), `versionForm`, `testPage`, `impact`, `easeOfAttack`.
- **Location:** the HTML file and the line of the bootstrap `<script>` tag.
- **Remediation:** Serve SAPUI5 through the approuter instead of a public CDN: route `resources/` to the `ui5` destination or to the HTML5 Application Repository, so the version is controlled by the landscape and does not change behind a deployed app. Where the CDN must stay, pin a specific version (`https://ui5.sap.com/1.120.3/resources/sap-ui-core.js`) rather than the evergreen or unversioned form, and add `integrity="sha384-…"` with `crossorigin="anonymous"` to the bootstrap script, knowing that they protect only the loader: the libraries it fetches at run time are still trusted blindly. Keep the pinned version inside maintenance, since the CDN removes versions one year after their end of maintenance.
- **References:** <https://ui5.sap.com/#/topic/2d3eb2f322ea4a82983c1c62a33ec4ae> (Variant for Bootstrapping from Content Delivery Network), <https://me.sap.com/notes/3001696> (SAP Note 3001696), <https://owasp.org/Top10/2025/A08_2025-Software_or_Data_Integrity_Failures/>
- **Limits / what does not trigger:**
  - A bootstrap served relative to the page (`resources/sap-ui-core.js`, `/resources/sap-ui-core.js`), which is what the approuter `ui5` destination and the HTML5 Application Repository produce, is never reported, whatever version segment its path carries; neither is a `src` with a scheme other than `http(s)` (recorded as `[non-http]`).
  - An external bootstrap with an `integrity` attribute is not reported, even with the `latest` form and even though SRI covers only the loader: the rule checks the page's own defence, not the run-time loading of libraries. The attribute's value is never read, so a wrong or stale hash (which would make the browser block the script) is not detected either; the page would fail visibly.
  - `host` is recorded as an identifier of the CDN only when it has the shape of a DNS name or dotted IPv4 address; a bracketed IPv6 host, an empty host or an unparsable `src` is recorded as `null`, and the finding still fires because the collector flagged the bootstrap as external.
  - Only `<script>` tags that the collector recognises as a bootstrap count (`id="sap-ui-bootstrap"` or a `src` ending in `sap-ui-core.js`). Bootstraps assembled at run time (`sap-ui-core-nojQuery.js`, loaders injected by JavaScript, `ui5loader.js`, frameworks that write the tag) and pages generated at build time (`gen/`, `dist/`) are not seen, and the walk stops after 200 HTML bootstraps.
  - The rule does not check whether the pinned version is still in maintenance or still on the CDN; `UI5_OUT_OF_MAINTENANCE` covers the version served by a deployed app. A `specific` version that the CDN has removed (SAP Note 3001696: one year after end of maintenance) fails at run time, which is an availability problem rather than an integrity one.
  - The SAPUI5 CDN topic was verified through the `SAP-docs/sapui5` GitHub mirror (`docs/04_Essentials/variant-for-bootstrapping-from-content-delivery-network-2d3eb2f.md`: "The default version of our libraries has the generic URL `https://ui5.sap.com/resources/sap-ui-core.js`", "The specific version allows you to select a particular fixed version for bootstrapping", "The evergreen version allows you to automatically select the latest available patch level", "SAP removes SAPUI5 versions from the SAPUI5 CDN one year after their end of maintenance. For more information, see SAP Note 3001696"; the word "integrity" does not appear in the topic), and the bootstrap description through `docs/04_Essentials/bootstrapping-loading-and-initializing-a04b0d1.md` ("Required files are loaded dynamically using XMLHttpRequest (XHR)", "You can access the libraries externally from a CDN, which can be either an SAP-hosted CDN or a custom-hosted CDN"). `ui5.sap.com` does not resolve from the build environment, so the link is the canonical topic URL that file publishes to. SAP Note 3001696 is cited by that topic; `me.sap.com` does not resolve either and requires an SAP account, so the link is the canonical note URL and its content was not read. The OWASP link follows the `A08_2025-Software_or_Data_Integrity_Failures` entry in the OWASP/Top10 `2025/mkdocs.yml`, whose page names applications that rely "upon plugins, libraries, or modules from untrusted sources, repositories, and content delivery networks (CDNs)".
